# GitHub PR Explorer — Release Notes v0.3.0

**March 10, 2026** · covers February 11 – March 10

This release makes the app a place you can finish a review, not just start
one: verdicts post to GitHub from the merge queue, and reviews are stored as
structured data instead of free-form markdown.

## Highlights

- **Post a verdict from the app.** Merge queue cards have a Verdict button that
  opens a composer. Pick Approve / Request Changes / Comment, toggle which
  review sections go in the body, add your own text, and post. A draggable
  review panel sits alongside for reference.
- **Selective inline comments.** Choose which issues to post instead of all of
  them. The verdict composer has an **Inline** toggle per section so issues
  land as line comments rather than body text. Buttons to post critical, major
  or minor issues in one click.
- **Structured JSON reviews.** Reviews are saved as validated JSON (sections,
  issues, locations, score) with markdown generated from it. Inline comments,
  verdicts and scores no longer depend on regex parsing. Existing reviews were
  migrated.
- **Reviewer avatars on cards.** Each requested reviewer shows with a
  green (approved) or red (changes requested) ring and a state icon.
- **Drag-and-drop merge queue** replaces the up/down arrows. Draft badge on
  queue items.
- **Live CI status.** PR list and merge queue poll every 60 seconds so badges
  stop going stale. Duplicate and cancelled check runs are handled.
- **PR number search** on the Advanced tab, resolved server-side.
- **More resilient GitHub calls.** Retries on 502/503/504, cached stats
  survive empty API responses, bounded caches and sanitized error messages.
- **Review polling recovers after a page refresh.** Local time on queue notes.
