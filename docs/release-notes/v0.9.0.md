# GitHub PR Explorer — Release Notes v0.9.0

**August 31, 2026** · covers August 31

## Highlights

### Automation tab and the auto-review pipeline

New PRs in allowlisted repos are detected, classified by file-pattern rules,
and reviewed automatically by the right agent. The **Automation** tab is
where you configure it, and `docs/AUTOMATION.md` is the operator's guide.

- **Routing rules.** File patterns map to a reviewer (PB reviewer, ED
  reviewer, code reviewer) with ignore patterns for index files. A seed script
  installs the standard Scala ruleset with scope **off**, so nothing dispatches
  until you turn it on.
- **Dispatch gates.** A PR is reviewed only when it is not a draft, CI passes,
  and it is no more than 10 commits behind base (all configurable). Waiting
  PRs show ⏳ with the reason. Open PRs wait as long as they stay open.
- **Manual control everywhere.** A 🤖+ / 🤖− toggle on PR list rows and cards
  enrolls or opts out any PR. Opt-outs survive backfills.
- **Pipeline table** in the Automation tab lists every enrolled PR with
  status, reason, last check, and current review state. Merged and closed PRs
  are hidden.
- **Active-config strip** shows the configuration the pipeline is actually
  running with, separate from the unsaved draft below it.
- **Backfill script** enrolls PRs that were open before automation was
  enabled. Pipeline size is capped (default 1000).

### Reviews that survive change

- A running review is **stopped and restarted** when new commits land, with a
  PR comment naming both SHAs.
- Reviews interrupted by a **service restart** are found at startup, closed as
  "lost in a service restart," and re-run.

### Visibility

- **Running-now strip** at the top of Review Logs shows what is executing
  right now, or says explicitly that nothing is.
- **🤖 ✓ Armed** badge on PR list cards, not only queue and board cards.

### Rate limit fix

The dispatch worker checked each pending PR individually and could burn the
entire shared GitHub GraphQL quota. It now makes one call per repo per cycle,
cutting its usage from roughly 2,400 to 60 calls per hour.
